### 4. `deploy.yml`'s `schedule`/`workflow_dispatch` triggers bypass the CI gate the file's own top comment claims — deliberately left as-is

Found 2026-07-31 during the third bug-hunt pass's full trace of `.github/workflows/*.yml`.
`deploy.yml`'s top comment states: _"Gated on CI (not `push`)... a commit that fails
tests/lint/build never reaches production."_ That's only true for the `workflow_run` trigger
(`deploy.yml:30`'s `if:` correctly checks `github.event.workflow_run.conclusion == 'success'`).
For the `schedule` (daily cron) and `workflow_dispatch` (manual) triggers, the same `if:`
short-circuits to "proceed unconditionally" — the code's own inline comment (`deploy.yml:28-29`)
already documents this: _"schedule/workflow_dispatch have no workflow_run context and always
proceed."_ Since `main` has no branch protection (also noted in the top comment), a broken
commit that CI correctly blocks from `workflow_run`-triggered deploy would still go out on the
next midnight cron tick, or via a manual dispatch — `npm run build` alone (what the deploy job
runs) doesn't cover Prettier format-check, `npm audit`, Playwright e2e, or Lighthouse CI, all
of which are CI (`ci.yml`)-only gates.

**Explicitly reviewed with the user 2026-07-31 — decision: leave the code and comment as-is,
just track it here.** Not fixed and not planned; revisit only if it causes a real incident
(e.g. a genuinely broken `main` gets deployed via cron/dispatch).
